# 既存歌詞の同期方式選択

保存した音源の「⋮ → 歌詞の同期方法を選ぶ」から選ぶ。先にLRCLIBまたはファイルから歌詞を保存する。

## 指でなぞって保存

- 行・単語を切り替え、曲を再生しながら次の歌詞を順になぞる。
- 指が触れた再生時刻を開始、次の単語への移動または指を離した再生時刻を終了として記録する。文字数から時刻を作らない。
- 記録済みは緑、触れている部分は金色。再生・停止・シーク・スクロール切り替え・1つ戻す・最初からやり直しに対応。
- 下書きは音源ID・URI・音声ハッシュ・歌詞本文・行/単語モードで分離し、端末内へatomicに保存。閉じる操作、画面再作成やアプリ再起動後はメニューから同じ方式を開いて再開できる。
- 全部分の時刻が揃ってから新しい歌詞リビジョンとして保存。元の本文、音源、以前の歌詞は残る。単語モードはEnhanced LRCに時刻を出力できる。
- AIが付けた既存時刻は同じ行・単語境界に対応する場合だけ引き継ぐ。未記録部分を補える。複数行がまとめられたAI候補は勝手に時間配分せず、なぞって分割する。

## AIで秒数を推定（実験版）

- small/mediumを選び、端末内Whisperで音声認識した区間と既存歌詞を単調順序で照合する。同じ音源ID・URI・ハッシュ・モデルの認識結果は再利用する。
- これは専用の強制アライメントモデルではない。日本語の歌唱を正確に整列できると確認したライブラリは追加していない。AIの単語時刻生成は未実装。
- NFKC・かな正規化と文字列距離で照合し、短すぎる曖昧な一致、低い認識信頼度、大きな区間の隔たりを除外する。表示本文をASR結果で置き換えない。
- 複数の歌詞行が1つの認識区間に対応するときはまとめた区間を保持する。行・単語へ比例配分しない。照合スコアは時刻精度の確率ではない。
- 十分な一致がない行は`startMs=endMs=-1, alignment=unmatched`。プレーヤーでは未同期と表示してタップシークを付けない。未同期が残る間は本文・JSONのみ書き出せる。
- 元歌詞のJSONをキューに固定してから処理する。取消後の保存を防ぎ、処理失敗でも現在の歌詞を保持する。既存のフォアグラウンドサービス・直列キュー・温度監視・中断復旧を再利用する。
- 音声認識、照合、なぞり記録には通信しない。モデルの初回取得とユーザーが選んだ歌詞検索だけがネットを使う。

## 保存と変更ファイル

SQLite v4→v5では`lyrics_tasks.input_document`と`lyrics_recognition_cache`を追加する。既存の曲、履歴、歌詞、曲情報を削除しない。v1〜v3からの移行も既存テストに含める。

新規: `LyricsSyncUi`、`LyricsTraceView`、`LyricsTraceSession`、`LyricsTraceDrafts`、`ReferenceLyricsAlignment`。
更新: `LyricsSourcesUi`、`LyricsUi`、`LyricsView`、`Lyrics`、`LyricsStore`、`LyricsService`、`DownloadStore`、`MainActivity`。
テスト: `LyricsTraceSessionTest`、`ReferenceLyricsAlignmentTest`、`DownloadStoreTest`、`LyricsSyncModesTest`、任意の`DeviceReferenceSyncTest`。

実機テストの通常fixtureは自作日本語音声とその実際の認識結果。第三者の歌詞・音声・画像はGitや通常APKに含めない。実曲テストはユーザーが指定した端末内ファイルと取得済み歌詞を使う明示的opt-inで実行する。
