# 歌詞の開始・停止と操作画面の修正

## 症状と修正

ユーザーの症状は「処理が始まらない・途中で止まる」。実機ログは今回取得していないため、端末で起きた個別の停止原因は確定していない。コードで確認した問題を修正し、PC上で回帰テストを追加した。

- 以前は認識データが未取得だとモデル管理へ移るだけで、取得後に歌詞解析を開始する必要があった。取得タスクと希望した解析を同じトランザクションで順に登録し、取得完了後に自動で解析へ進める。
- データを複数の曲で共有する登録処理について、既存タスクを返すときの入れ子トランザクションのロールバックを回帰テストで検出・修正した。重複ダウンロードと、登録したつもりの解析が消える問題を防ぐ。
- データ取得が失敗・中止になった場合は、待機中の関連解析も再試行できる状態で止める。他モデルの処理や保存済み歌詞は変更しない。
- 解析プロセスが終了するとSQLiteだけに「処理中」が残る可能性があった。サービスが1秒ごとに生存時刻を記録し、アプリは60秒以上応答がない処理を失敗状態へ移す。遅れて戻った旧結果は保存しない。
- 解析中は対象の音声区間を表示する。最初の30秒の推論中に「モデル読み込み中」と表示し続けない。根拠のない推定進捗や残り時間は出さない。
- 通信中断の理由を表示し、部分ファイルからの再取得を案内する。モデルのSHA-256不一致は、次の試行で再取得できるようにする。

## 新しい操作

曲の「⋮ → 歌詞」、またはプレーヤーの「歌詞を探す / 歌詞の取得・同期」からひとつの歌詞画面を開く。

- 歌詞がなければ検索・貼り付けを表示する。
- 歌詞があれば表示・タイミング調整を表示する。
- 処理中は取得/認識/同期の現在段階・進捗と中止を表示する。
- 失敗理由と再試行は画面内に残す。再試行では詳細設定の現在値を使い、同期対象の本文は元のスナップショットを使う。
- ファイル読み込み、本文編集、音声認識、履歴、書き出し、モデル選択は「その他の方法・設定」へまとめる。
- モデル選択はsmall/mediumの単一選択と取得状況に整理する。取得・中止・削除を必要な状態でだけ表示する。
- 通知から対象曲の進捗を直接開き、画面再作成後も進捗画面を復元する。

SQLite v5→v6は`lyrics_tasks.heartbeat_ms`の追加のみ。曲ID、URI、歌詞・時刻・履歴、同期入力と認識キャッシュを保持する。v1〜v4の既存移行にも対応する。

## PCでの検証

`DownloadStoreTest`で初回の取得→解析登録、同じデータを使う複数曲、取得失敗/中止の伝播、停止プロセスの復旧、v5データ移行を確認する。
`LyricsFlowUiTest`で通常メニューの集約、未取得/保存済み/取得中/失敗表示、中止、通知、画面再作成を検証する。RobolectricのAndroid描画機能を使い、自作歌詞の画面PNGも生成・確認する。

モデル配布先には本文をダウンロードしない接続確認を行い、smallの通常取得はHTTP 200、途中からの取得はHTTP 206と正しい全体サイズが返ることを確認した。音声・歌詞を送信していない。

PCのAndroidエミュレーターは、仮想化ドライバー未導入で、ソフトウェア起動も失敗した。この更新でのAPKの実行、実際のモデル取得からWhisper推論までの通し確認、実機のメモリ不足・発熱による停止の再現は未実施。PCテストはキュー/永続化/Android UIの検証であり、実機性能の検証ではない。Whisperの歌唱認識精度とAI同期の品質は今回変更していない。
