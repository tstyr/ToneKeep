# 歌詞・曲情報取得の通信エラーと表示更新

ユーザー報告「歌詞・アルバム情報を取得できず通信エラーが出る」を受け、PCで実際の取得先とアプリの通信コードを確認した。

## 切り分け結果

- LRCLIBの検索とID取得がHTTP 503を返した。応答は `ServerOverloaded`、`Retry-After: 1`。曲名やAPIキーの不足を示す応答ではない。
- MusicBrainzとCover Art Archiveは応答した。修正後の実アプリコードをPCのRobolectric環境から実行し、曲情報・アルバム・画像取得、JPEG保存、SQLiteへの反映まで成功。画像は100,834 bytes、処理約9.5秒。
- 同じ実アプリコードでのLRCLIB取得は、短い待機を挟む最大3回の試行後も503。約5.9秒で取得先名とHTTP番号を持つエラーとして終了した。実サービスからの歌詞取得成功は、この検証では確認できていない。
- これはPCの接続確認であり、ユーザー端末の通信エラーが同一原因であると断定するものではない。端末のエラー文・DNS・TLS経路の確認は別途必要。

## アプリ側の修正

| 対象 | 変更 |
| --- | --- |
| `MetadataHttp.java` | 通信全体を1つのロックで囲む処理を廃止。取得元ごとに直列化し、画像の取得が別サービスの歌詞検索を待たせないようにした。同一サービスへの間隔は維持する。 |
| 同上 | 処理予算20秒と接続/読取タイムアウトを適用。短い`Retry-After`を守る限定再試行とジッターを追加。長い待機時間は保存して守り、無制限に再試行しない。HTTPS、転送先制限、サイズ制限、TLS検証は維持する。 |
| 同上 | LRCLIB/MusicBrainz/画像配信元を区別し、503・429・403・DNS・TLS・時間切れなどの理由を表示。JSONを要求したのにHTML等が返る場合も識別する。 |
| `SongDetails.java`, `LyricsSourcesUi.java` | 検索前は曲名・曲長の確認に限定し、音源全体のハッシュ計算を歌詞保存時へ移動。保存時は音源を再確認する。検索文字列はUIスレッドで読み取る。 |
| `MusicCatalog.java` | 選択した曲名・アーティスト・アルバムを画像より先に保存する。画像エラーで曲情報を失わない。小さい画像への再取得は404/サイズ超過時に限定し、タイムアウト時に同じ待機を重ねない。 |
| `LyricsSourcesUi.java` | 画像だけ失敗した場合は「曲情報は保存しました」と理由を残し、画像を再取得できるようにした。 |
| `MetadataEnricher.java`, `TrackMetadata.java` | 配信元JSONのnullを文字列`null`の曲名・アーティストとして保存しない。旧版の配信元タグにこの値が保存されている場合は、保存行を書き換えず読み取り時に未取得として扱う。確認済みのMusicBrainz等の値は変更しない。 |
| `TrackMetadata.java` | アルバムだけの変更や、同じ文字数の変更も一覧へ反映。文字数合計による表示キャッシュを保存時の更新番号へ変更。DBスキーマ変更なし。 |
| `PlaybackCore.java`, `MainActivity.java` | 取得した曲情報を、再生のやり直しなしで現在のプレーヤーと通知へ反映。再生位置・再生/停止状態は保持する。 |

音源・ハッシュ・ファイルパスを情報取得先へ送信する機能は追加していない。追加SDK・APIキー・新しい取得先もない。歌詞サービスが503を返している間は、取得成功を保証できない。既存の歌詞表示・貼り付け・ファイル読込・端末内の同期は引き続き利用できる。

## テスト

- `MetadataHttpTest`: 503からの回復と試行上限、429の待機保持、画像取得中の別サービス接続、不正転送・サイズ超過・HTML・TLS・処理予算の検査。
- `MetadataAcquisitionTest`: 検索時に音源全体を読まないこと、保存時のハッシュ、nullタグ、画像待機前のアルバム保存、限定的な画像フォールバック、一覧更新、URI分離と音源保持。
- `PlaybackNotificationTest`: 曲情報更新が現在の再生位置・状態を変えず通知へ反映されること。
- 外部サービスの実接続プローブは`.tools/`内で実行し、通常CIの単体テストへ混ぜない。外部の歌詞・音源・ジャケットをリポジトリやテストfixtureへ追加しない。

LRCLIBの503と待機ポリシーは[公式API資料](https://lrclib.net/docs#errors)を参照。


## ローカル検証結果

通常のGradle検証は単体テスト103件成功（失敗/スキップ0）、lintエラー0・既存警告16、アプリAPKとAndroidテストAPKの生成成功。外部接続プローブのLRCLIB失敗は通常テストへ含めず、上記の取得先不調として別に記録した。Galaxy実機でのネット接続確認は未実施。
