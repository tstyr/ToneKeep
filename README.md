# ToneKeep

曲名から音楽を探し、配信元で入手できる最高品質の音声を保存するAndroidアプリです。yt-dlp・FFmpeg・Python・QuickJSを端末内に同梱します。専用サーバーやAPIキーは不要です。Android 10以降、arm64-v8a / armeabi-v7a / x86_64に対応した検証版です。

## 検索・保存

1. **YouTube / SoundCloud** から検索先を選び、曲名やアーティスト名を入力します。
2. または **yt-dlp対応サイトの音源ページURL** を貼り付けます。URL入力では検索先の指定は使いません。ほかのアプリの「共有」からもURLを受け取れます。
3. 音源を選んで、形式・推定容量を確認します。
4. **最高品質を自動選択** または音声形式を指定して保存します。

保存先は **ダウンロード / ToneKeep** です。通知付きのフォアグラウンドサービスで画面を閉じても処理を続け、完了後はMediaStoreで共有ダウンロードフォルダーへ書き込みます。広範なストレージ権限は不要です。

## プレイリスト・一括バックグラウンド保存

1. 対応サイトのプレイリストURLを入力し、**プレイリスト全曲を読み込む** を押します。
2. **全選択**、または曲ごとのチェックで保存対象を指定します。画面にまだ表示していない曲も全選択の対象です。
3. **選択した曲を一括保存** を押すと、最高品質の自動選択で、一覧の順番に1曲ずつ保存します。
4. **保存した音源** で、グループごとの完了・処理中・待機・失敗・中止数を確認できます。グループの一括中止、失敗した曲だけの再試行にも対応します。

全曲読み込みには検索用の12件制限を適用しません。取得元が返す全項目を読み込み、非公開・削除済み・ライブ中の項目や同じURLの重複を除外して件数を表示します。取得元が項目を隠す場合やアクセス制限がある場合は、その項目を取得できません。一括保存時には、処理中・保存済みのURLも除外します。削除したファイルを再取得する場合は、個別の履歴から再ダウンロードしてください。

検索結果から複数曲を選んでまとめて保存することもできます。多数の曲は表示を段階的に増やせます。処理中の曲を履歴の先頭に表示し、待機順とグループの集計を確認できます。キューはSQLiteに保存し、以前の1.1版の履歴を初回に移行します。画面回転で読み込み済みの一覧と選択を保持します。プロセス自体が終了した後は一覧を再取得する必要がありますが、確定した保存キューと履歴は残ります。

**Spotify音源の直接保存、およびSpotifyプレイリストの曲一覧の自動取り込みは現在非対応です。** Spotifyのプレイリスト情報と、別の配信元にある音源は別物です。今回はyt-dlp対応サイトの一括保存を対象にしています。

履歴から進捗確認、中止、再試行、保存済み音源をプレーヤーで開く操作ができます。中止後の遅延コールバックで完了状態を上書きしない構成です。プロセスが終了した場合は、次にアプリを開いたときに中断を検出して再試行できます。Wi-Fi限定設定は新規の保存に適用され、接続が切れた場合は処理を停止して履歴に理由を表示します。

## テンポを変えずに曲全体のキーを変更

1. **キー変更 → 端末の音声ファイルを選ぶ** で音源を読み込みます。保存済みの曲は **音源 → この音源のキーを変更** から選べます。
2. スライダーか±ボタンで **−12〜＋12半音** を指定します。声質をなるべく保ちたい場合は **声の自然さを優先（フォルマント保持）** を有効にします。
3. **FLAC（24bit）／WAV（24bit）** を選び、**テンポを保ってキー変更・保存** を押します。原本を残し、ダウンロード / ToneKeepへ別ファイルで保存します。

ボーカルと伴奏を含むミックス全体を一緒に処理します。ボーカル分離、パート別のキー変更、再生中のリアルタイムプレビューは行いません。Rubber Bandの音程処理を品質優先・左右連動で実行し、元のサンプルレートとチャンネル数を維持します。浮動小数点の中間音声でピークを調べ、必要な場合だけ出力を−0.1dB以下に下げてクリッピングを抑えます。

FLAC／WAVへの保存で追加の非可逆圧縮を避けますが、キー変更による音の変化はあります。大きな変更では特に音の質感が変わります。24bit保存によって元音源の品質が上がるわけではありません。フォルマント保持は楽器の音色にも作用するため、曲に合わせて切り替えてください。

処理は端末内で行い、ネット接続やSpotify Premiumは不要です。ダウンロードとキー変更は別々のキューで処理し、同時に各1件を実行できます。進捗・中止・再試行は履歴から操作できます。読み込み元・浮動小数点の中間ファイル・完成ファイルの一時容量が必要です。長い音源は数百MB以上を使う場合があります。外部ストレージやクラウドの音源は、再試行時にも読み取り権限とアクセスが必要です。

## 音質・対応サイト

自動選択はyt-dlpの `bestaudio/best` を使用します。音声専用ストリームを優先し、取得元に音声専用版がない場合は映像付きファイルからFFmpegで音声を抽出します。`--audio-format best` により元の音声形式を優先し、MP3やFLACへの変換は強制しません。音質は配信元の音源が上限です。OpusやM4Aなどの非可逆音源をFLACに変換しても元の品質は上がりません。

曲名検索は各サービスの検索結果を最大12件表示します。全サイト横断検索ではありません。URL入力は[yt-dlpの対応サイト](https://github.com/yt-dlp/yt-dlp/blob/master/supportedsites.md)が対象ですが、サイト側の変更、地域制限、アクセス制限などで取得できない場合があります。ライブ配信中、ログイン必須、DRMで保護されたコンテンツには対応しません。保存・利用する権利のあるコンテンツに使用してください。

同梱yt-dlpは **2026.10.21** 版です。公式配布ファイルのSHA-256を検証したうえで組み込み、初期化時にも同梱ファイルを検証します。検索画面の **yt-dlpを更新** で公式の安定版へ更新できます。ネイティブ実行環境の更新にはAPKの再ビルドが必要です。

## GitHubからAPKをダウンロード

1. リポジトリの **Releases → ToneKeep Preview** を開きます。
2. **Assets → ToneKeep-preview.apk** をAndroid端末にダウンロードします。
3. APKを開いてAndroidの案内に従いインストールします。必要に応じて使用したブラウザーの「不明なアプリのインストール」を許可します。

`main` へのpush、または **Actions → Android APK → Run workflow** で単体テスト・lint・ビルド・音声取得テストが実行され、成功するとAPK付きのプレリリースが作成されます。PRでは検証とビルドのみを行います。ActionsのArtifactからも30日間取得できます。

複数のCPU用ランタイムを同梱するため、APKは約150MBです。APKは[公開テスト鍵](.ci/README.md)で署名した検証版です。本番配布には別のアプリIDと非公開の署名鍵を使用してください。

## ビルドと検証

必要環境はJDK 17、Android SDK Platform 35 / Build Tools 35.0.0です。`local.properties` の `sdk.dir` か `ANDROID_HOME` を設定します。

```powershell
.\gradlew.bat :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
```

出力は `app/build/outputs/apk/debug/app-debug.apk` です。macOS/Linuxでは `./gradlew` を使います。Nativeの実行ファイルをAndroidのネイティブライブラリー領域へ展開するため、`useLegacyPackaging` が必要です。

```sh
python scripts/smoke_ytdlp.py
python scripts/smoke_pitch.py
```

上のテストにはホスト側のFFmpeg / ffprobeが必要です。同梱yt-dlpのチェックサムを検証し、自作した1秒のWAV音源をローカルHTTPサーバーで配信して、メタデータ取得 → 最高品質選択 → 取得 → 音声抽出まで実行します。外部サイトのメディアはダウンロードしません。出力のコーデックとサンプルレートも確認します。

キー変更テストにはJDK 17とRubber Band対応のホストFFmpegも必要です。アプリと共通の処理設定で自作ステレオ音源を＋3／−5／＋12半音へ変換し、出力の周波数、曲の長さ、拍の間隔、24bit・48kHz・2チャンネル、ピーク上限、原本のチェックサムを確認します。ビルド済みAPKがあれば、3種類のCPU向けランタイムがRubber Bandを含むことも確認します。

テストは検索先の選択、URL・形式・メタデータの解析、全件読み込みの要求、重複・取得不可項目の除外、ファイル名処理を確認します。RobolectricのAndroidテスト環境では、1,000曲のキュー保存と全選択、旧履歴の移行、曲順、失敗した曲の再試行、中止後の状態保持、画面状態が大きなBundleにならないことも検証します。RSSのテスト用プレイリストでは15件を取得し、検索用12件制限がないことを確認します。

キー変更画面のファイル選択、±操作、画面再生成後の設定保持、処理キューの保存・再試行、1.2版からのデータベース移行も検証します。

これらのテストはAndroid実機のネイティブ実行、通知、MediaStoreを検証するものではありません。実機での検索・保存・キー変更・中止・Wi-Fi切断の確認は別途必要です。Androidによる強制終了やバックグラウンド処理の時間制限では停止する場合があり、履歴から再試行できます。

## データ・ライセンス

検索語や入力URLを、検索先・配信元およびその関連ホストへ送信します。アプリ固有の広告・解析SDKはありません。履歴として音源ページURLまたは読み込み元URI、タイトル、選択形式、キー変更の設定、進捗、グループ、保存先URIを端末内のSQLiteに記録します。認証情報やCookieを入力・保存する機能はありません。アプリ削除で履歴と一時ファイルは削除されますが、共有ダウンロードフォルダーの音源は残ります。
